# RFC-001 — Mise à jour du pare-feu

> Contexte réel du lab : la VM pare-feu tourne sous **OPNsense 25.1** ; la version cible du support est **26.7**. En production NovaTech, l'équivalent serait pfSense (choix du dossier) vers la dernière version mineure stable.

```
RFC-001 : mise à jour du pare-feu (OPNsense 25.1 → 26.7)
Demandeur      : Antonin Moisan, administrateur infrastructure
Date           : 03/11/2026
Type           : normal
Description    : migration de version majeure du pare-feu OPNsense (25.1 → 26.7),
                 reconduite de la configuration (interfaces VLAN 20/30/40, règles,
                 NAT bastion, DHCP).
Justification  : correctifs de sécurité ; version 25.1 ancienne et en fin de
                 maintenance ; conformité au plan de mises à jour (§4).
Impact         : coupure de TOUS les flux (WAN + inter-VLAN + NAT) estimée à
                 5 à 10 min ; baux DHCP conservés ; aucun accès distant pendant
                 la fenêtre.
Risque (2) x Probabilité (2) = 4 (modéré)  [régression des règles NAT,
                 perte de config, échec du boot]
Plan de test   : 1) ping inter-VLAN depuis le bastion (10.10.10.254)
                 2) accès GUI https://localhost:8443 via tunnel
                 3) règle NAT bastion : ssh etudiant@10.38.10.10
                 4) vérifier les règles OPT1/2/3 puis export de la config
Retour arrière : snapshot "socle-OK" (qm rollback 100 socle-OK) et/ou
                 restauration du config.xml exporté (03/11/2026)
Fenêtre        : vendredi 06/11/2026, 18h00 — hors heures ouvrées
Décision CAB   : approuvée (voir PV-CAB-001)
Conditions     : snapshot + export config AVANT ; tests APRES ; délai max 30 min
                 au-delà duquel le retour arrière est déclenché sans nouvelle
                 délibération
```
